# PRD Authoring

- Start from the user problem and the outcome, not the solution.
- Number every requirement and give each one testable acceptance criteria.
- Separate must-have from nice-to-have; state explicit non-goals.
- List open questions and assumptions rather than silently deciding.
- Keep it short enough to read in one sitting; link out for detail.
